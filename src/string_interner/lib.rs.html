6//! Caches strings efficiently, with minimal memory footprint and associates them with unique symbols.
7//! These symbols allow constant time comparisons and look-ups to the underlying interned strings.
8//!
9//! ### Example: Interning & Symbols
10//!
11//! ```
12//! use string_interner::StringInterner;
13//!
14//! let mut interner = StringInterner::default();
15//! let sym0 = interner.get_or_intern("Elephant");
16//! let sym1 = interner.get_or_intern("Tiger");
17//! let sym2 = interner.get_or_intern("Horse");
18//! let sym3 = interner.get_or_intern("Tiger");
19//! assert_ne!(sym0, sym1);
20//! assert_ne!(sym0, sym2);
21//! assert_ne!(sym1, sym2);
22//! assert_eq!(sym1, sym3); // same!
23//! ```
24//!
25//! ### Example: Creation by `FromIterator`
26//!
27//! ```
28//! # use string_interner::DefaultStringInterner;
29//! let interner = ["Elephant", "Tiger", "Horse", "Tiger"]
30//!     .into_iter()
31//!     .collect::<DefaultStringInterner>();
32//! ```
33//!
34//! ### Example: Look-up
35//!
36//! ```
37//! # use string_interner::StringInterner;
38//! let mut interner = StringInterner::default();
39//! let sym = interner.get_or_intern("Banana");
40//! assert_eq!(interner.resolve(sym), Some("Banana"));
41//! ```
42//!
43//! ### Example: Iteration
44//!
45//! ```
46//! # use string_interner::{DefaultStringInterner, Symbol};
47//! let interner = <DefaultStringInterner>::from_iter(["Earth", "Water", "Fire", "Air"]);
48//! for (sym, str) in &interner {
49//!     println!("{} = {}", sym.to_usize(), str);
50//! }
51//! ```
52//!
53//! ### Example: Use Different Backend
54//!
55//! ```
56//! # use string_interner::StringInterner;
57//! use string_interner::backend::BufferBackend;
58//! type Interner = StringInterner<BufferBackend>;
59//! let mut interner = Interner::new();
60//! let sym1 = interner.get_or_intern("Tiger");
61//! let sym2 = interner.get_or_intern("Horse");
62//! let sym3 = interner.get_or_intern("Tiger");
63//! assert_ne!(sym1, sym2);
64//! assert_eq!(sym1, sym3); // same!
65//! ```
66//!
67//! ### Example: Use Different Backend & Symbol
68//!
69//! ```
70//! # use string_interner::StringInterner;
71//! use string_interner::{backend::BucketBackend, symbol::SymbolU16};
72//! type Interner = StringInterner<BucketBackend<SymbolU16>>;
73//! let mut interner = Interner::new();
74//! let sym1 = interner.get_or_intern("Tiger");
75//! let sym2 = interner.get_or_intern("Horse");
76//! let sym3 = interner.get_or_intern("Tiger");
77//! assert_ne!(sym1, sym2);
78//! assert_eq!(sym1, sym3); // same!
79//! ```
80//!
81//! ## Backends
82//!
83//! The `string_interner` crate provides different backends with different strengths.
84//! The table below compactly shows when to use which backend according to the following
85//! performance characteristics.
86//!
87//! - **Fill:** Efficiency of filling an empty string interner.
88//! - **Resolve:** Efficiency of resolving a symbol of an interned string.
89//! - **Allocations:** The number of allocations performed by the backend.
90//! - **Footprint:** The total heap memory consumed by the backend.
91//! - **Contiguous:** True if the returned symbols have contiguous values.
92//! - **Iteration:** Efficiency of iterating over the interned strings.
93//!
94//! | **Property** | **BucketBackend** | **StringBackend** | **BufferBackend** |
95//! |:-------------|:-----------------:|:-----------------:|:-----------------:|
96//! | **Fill**     | ok                | good              | best              |
97//! | **Resolve**  | best              | good              | bad               |
98//! | Allocations  | ok                | good              | best              |
99//! | Footprint    | ok                | good              | best              |
100//! | Contiguous   | yes               | yes               | no                |
101//! | Iteration    | best              | good              | bad               |
102//!
103//! ## When to use which backend?
104//!
105//! ### Bucket Backend
106//!
107//! Given the table above the `BucketBackend` might seem inferior to the other backends.
108//! However, it allows to efficiently intern `&'static str` and avoids deallocations.
109//!
110//! ### String Backend
111//!
112//! Overall the `StringBackend` performs really well and therefore is the backend
113//! that the `StringInterner` uses by default.
114//!
115//! ### Buffer Backend
116//!
117//! The `BufferBackend` is in some sense similar to the `StringBackend` on steroids.
118//! Some operations are even slightly more efficient and it consumes less memory.
119//! However, all this is at the costs of a less efficient resolution of symbols.
120//! Note that the symbols generated by the `BufferBackend` are not contiguous.
