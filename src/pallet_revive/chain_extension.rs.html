18//! A mechanism for runtime authors to augment the functionality of contracts.
19//!
20//! The runtime is able to call into any contract and retrieve the result using
21//! [`bare_call`](crate::Pallet::bare_call). This already allows customization of runtime
22//! behaviour by user generated code (contracts). However, often it is more straightforward
23//! to allow the reverse behaviour: The contract calls into the runtime. We call the latter
24//! one a "chain extension" because it allows the chain to extend the set of functions that are
25//! callable by a contract.
26//!
27//! In order to create a chain extension the runtime author implements the [`ChainExtension`]
28//! trait and declares it in this pallet's [configuration Trait](Config). All types
29//! required for this endeavour are defined or re-exported in this module. There is an
30//! implementation on `()` which can be used to signal that no chain extension is available.
31//!
32//! # Using multiple chain extensions
33//!
34//! Often there is a need for having multiple chain extensions. This is often the case when
35//! some generally useful off-the-shelf extensions should be included. To have multiple chain
36//! extensions they can be put into a tuple which is then passed to [`Config::ChainExtension`] like
37//! this `type Extensions = (ExtensionA, ExtensionB)`.
38//!
39//! However, only extensions implementing [`RegisteredChainExtension`] can be put into a tuple.
40//! This is because the [`RegisteredChainExtension::ID`] is used to decide which of those extensions
41//! should be used when the contract calls a chain extensions. Extensions which are generally
42//! useful should claim their `ID` with [the registry](https://github.com/paritytech/chainextension-registry)
43//! so that no collisions with other vendors will occur.
44//!
45//! **Chain specific extensions must use the reserved `ID = 0` so that they can't be registered with
46//! the registry.**
47//!
48//! # Security
49//!
50//! The chain author alone is responsible for the security of the chain extension.
51//! This includes avoiding the exposure of exploitable functions and charging the
52//! appropriate amount of weight. In order to do so benchmarks must be written and the
53//! [`charge_weight`](Environment::charge_weight) function must be called **before**
54//! carrying out any action that causes the consumption of the chargeable weight.
55//! It cannot be overstated how delicate of a process the creation of a chain extension
56//! is. Check whether using [`bare_call`](crate::Pallet::bare_call) suffices for the
57//! use case at hand.
58//!
59//! # Benchmarking
60//!
61//! The builtin contract callable functions that pallet-revive provides all have
62//! benchmarks that determine the correct weight that an invocation of these functions
63//! induces. In order to be able to charge the correct weight for the functions defined
64//! by a chain extension benchmarks must be written, too. In the near future this crate
65//! will provide the means for easier creation of those specialized benchmarks.
66//!
67//! # Example
68//!
69//! The ink-examples repository maintains an
70//! [end-to-end example](https://github.com/paritytech/ink-examples/tree/main/rand-extension)
71//! on how to use a chain extension in order to provide new features to ink! contracts.

86/// Result that returns a [`DispatchError`] on error.
87pub type Result<T> = core::result::Result<T, DispatchError>;

89/// A trait used to extend the set of contract callable functions.
90///
91/// In order to create a custom chain extension this trait must be implemented and supplied
92/// to the pallet contracts configuration trait as the associated type of the same name.
93/// Consult the [module documentation](self) for a general explanation of chain extensions.
94///
95/// # Lifetime
96///
97/// The extension will be [`Default`] initialized at the beginning of each call
98/// (**not** per call stack) and dropped afterwards. Hence any value held inside the extension
99/// can be used as a per-call scratch buffer.
100pub trait ChainExtension<C: Config> {
101	/// Call the chain extension logic.
102	///
103	/// This is the only function that needs to be implemented in order to write a
104	/// chain extensions. It is called whenever a contract calls the `seal_call_chain_extension`
105	/// imported wasm function.
106	///
107	/// # Parameters
108	/// - `env`: Access to the remaining arguments and the execution environment.
109	///
110	/// # Return
111	///
112	/// In case of `Err` the contract execution is immediately suspended and the passed error
113	/// is returned to the caller. Otherwise the value of [`RetVal`] determines the exit
114	/// behaviour.
115	///
116	/// # Note
117	///
118	/// The [`Self::call`] can be invoked within a read-only context, where any state-changing calls
119	/// are disallowed. This information can be obtained using `env.ext().is_read_only()`. It is
120	/// crucial for the implementer to handle this scenario appropriately.
121	fn call<E: Ext<T = C>, M: ?Sized + Memory<E::T>>(
122		&mut self,
123		env: Environment<E, M>,
124	) -> Result<RetVal>;
125
126	/// Determines whether chain extensions are enabled for this chain.
127	///
128	/// The default implementation returns `true`. Therefore it is not necessary to overwrite
129	/// this function when implementing a chain extension. In case of `false` the deployment of
130	/// a contract that references `seal_call_chain_extension` will be denied and calling this
131	/// function will return [`NoChainExtension`](Error::NoChainExtension) without first calling
132	/// into [`call`](Self::call).
133	fn enabled() -> bool {
134		true
135	}
136}
137
138/// A [`ChainExtension`] that can be composed with other extensions using a tuple.
139///
140/// An extension that implements this trait can be put in a tuple in order to have multiple
141/// extensions available. The tuple implementation routes requests based on the first two
142/// most significant bytes of the `id` passed to `call`.
143///
144/// If this extensions is to be used by multiple runtimes consider
145/// [registering it](https://github.com/paritytech/chainextension-registry) to ensure that there
146/// are no collisions with other vendors.
147///
148/// # Note
149///
150/// Currently, we support tuples of up to ten registered chain extensions. If more chain extensions
151/// are needed consider opening an issue.
152pub trait RegisteredChainExtension<C: Config>: ChainExtension<C> {
153	/// The extensions globally unique identifier.
154	const ID: u16;
155}
156
157#[impl_trait_for_tuples::impl_for_tuples(10)]
158#[tuple_types_custom_trait_bound(RegisteredChainExtension<C>)]
159impl<C: Config> ChainExtension<C> for Tuple {
160	fn call<E: Ext<T = C>, M: ?Sized + Memory<E::T>>(
161		&mut self,
162		mut env: Environment<E, M>,
163	) -> Result<RetVal> {
164		for_tuples!(
165			#(
166				if (Tuple::ID == env.ext_id()) && Tuple::enabled() {
167					return Tuple.call(env);
168				}
169			)*
170		);
171		Err(Error::<E::T>::NoChainExtension.into())
172	}
173
174	fn enabled() -> bool {
175		for_tuples!(
176			#(
177				if Tuple::enabled() {
178					return true;
179				}
180			)*
181		);
182		false
183	}
184}

186/// Determines the exit behaviour and return value of a chain extension.
187pub enum RetVal {
188	/// The chain extensions returns the supplied value to its calling contract.
189	Converging(u32),
190	/// The control does **not** return to the calling contract.
191	///
192	/// Use this to stop the execution of the contract when the chain extension returns.
193	/// The semantic is the same as for calling `seal_return`: The control returns to
194	/// the caller of the currently executing contract yielding the supplied buffer and
195	/// flags.
196	Diverging { flags: ReturnFlags, data: Vec<u8> },
197}

199/// Grants the chain extension access to its parameters and execution environment.
200pub struct Environment<'a, 'b, E: Ext, M: ?Sized> {
201	/// The runtime contains all necessary functions to interact with the running contract.
202	runtime: &'a mut Runtime<'b, E, M>,
203	/// Reference to the contract's memory.
204	memory: &'a mut M,
205	/// Verbatim argument passed to `seal_call_chain_extension`.
206	id: u32,
207	/// Verbatim argument passed to `seal_call_chain_extension`.
208	input_ptr: u32,
209	/// Verbatim argument passed to `seal_call_chain_extension`.
210	input_len: u32,
211	/// Verbatim argument passed to `seal_call_chain_extension`.
212	output_ptr: u32,
213	/// Verbatim argument passed to `seal_call_chain_extension`.
214	output_len_ptr: u32,
215}
216
217/// Functions that are available in every state of this type.
218impl<'a, 'b, E: Ext, M: ?Sized + Memory<E::T>> Environment<'a, 'b, E, M> {
219	/// Creates a new environment for consumption by a chain extension.
220	pub fn new(
221		runtime: &'a mut Runtime<'b, E, M>,
222		memory: &'a mut M,
223		id: u32,
224		input_ptr: u32,
225		input_len: u32,
226		output_ptr: u32,
227		output_len_ptr: u32,
228	) -> Self {
229		Self { runtime, memory, id, input_ptr, input_len, output_ptr, output_len_ptr }
230	}
231
232	/// The function id within the `id` passed by a contract.
233	///
234	/// It returns the two least significant bytes of the `id` passed by a contract as the other
235	/// two bytes represent the chain extension itself (the code which is calling this function).
236	pub fn func_id(&self) -> u16 {
237		(self.id & 0x0000FFFF) as u16
238	}
239
240	/// The chain extension id within the `id` passed by a contract.
241	///
242	/// It returns the two most significant bytes of the `id` passed by a contract which represent
243	/// the chain extension itself (the code which is calling this function).
244	pub fn ext_id(&self) -> u16 {
245		(self.id >> 16) as u16
246	}
247
248	/// Charge the passed `amount` of weight from the overall limit.
249	///
250	/// It returns `Ok` when there the remaining weight budget is larger than the passed
251	/// `weight`. It returns `Err` otherwise. In this case the chain extension should
252	/// abort the execution and pass through the error.
253	///
254	/// The returned value can be used to with [`Self::adjust_weight`]. Other than that
255	/// it has no purpose.
256	///
257	/// # Note
258	///
259	/// Weight is synonymous with gas in substrate.
260	pub fn charge_weight(&mut self, amount: Weight) -> Result<ChargedAmount> {
261		self.runtime.charge_gas(RuntimeCosts::ChainExtension(amount))
262	}
263
264	/// Adjust a previously charged amount down to its actual amount.
265	///
266	/// This is when a maximum a priori amount was charged and then should be partially
267	/// refunded to match the actual amount.
268	pub fn adjust_weight(&mut self, charged: ChargedAmount, actual_weight: Weight) {
269		self.runtime.adjust_gas(charged, RuntimeCosts::ChainExtension(actual_weight))
270	}
271
272	/// Grants access to the execution environment of the current contract call.
273	///
274	/// Consult the functions on the returned type before re-implementing those functions.
275	pub fn ext(&mut self) -> &mut E {
276		self.runtime.ext()
277	}
278
279	/// Reads `min(max_len, in_len)` from contract memory.
280	///
281	/// This does **not** charge any weight. The caller must make sure that the an
282	/// appropriate amount of weight is charged **before** reading from contract memory.
283	/// The reason for that is that usually the costs for reading data and processing
284	/// said data cannot be separated in a benchmark. Therefore a chain extension would
285	/// charge the overall costs either using `max_len` (worst case approximation) or using
286	/// [`in_len()`](Self::in_len).
287	pub fn read(&self, max_len: u32) -> Result<Vec<u8>> {
288		self.memory.read(self.input_ptr, self.input_len.min(max_len))
289	}
290
291	/// Reads `min(buffer.len(), in_len) from contract memory.
292	///
293	/// This takes a mutable pointer to a buffer fills it with data and shrinks it to
294	/// the size of the actual data. Apart from supporting pre-allocated buffers it is
295	/// equivalent to to [`read()`](Self::read).
296	pub fn read_into(&self, buffer: &mut &mut [u8]) -> Result<()> {
297		let len = buffer.len();
298		let sliced = {
299			let buffer = core::mem::take(buffer);
300			&mut buffer[..len.min(self.input_len as usize)]
301		};
302		self.memory.read_into_buf(self.input_ptr, sliced)?;
303		*buffer = sliced;
304		Ok(())
305	}
306
307	/// Reads and decodes a type with a dynamic size from contract memory.
308	///
309	/// Make sure to include `len` in your weight calculations.
310	pub fn read_as_unbounded<T: Decode>(&mut self, len: u32) -> Result<T> {
311		self.memory.read_as_unbounded(self.input_ptr, len)
312	}
313
314	/// The length of the input as passed in as `input_len`.
315	///
316	/// A chain extension would use this value to calculate the dynamic part of its
317	/// weight. For example a chain extension that calculates the hash of some passed in
318	/// bytes would use `in_len` to charge the costs of hashing that amount of bytes.
319	/// This also subsumes the act of copying those bytes as a benchmarks measures both.
320	pub fn in_len(&self) -> u32 {
321		self.input_len
322	}
323
324	/// Write the supplied buffer to contract memory.
325	///
326	/// If the contract supplied buffer is smaller than the passed `buffer` an `Err` is returned.
327	/// If `allow_skip` is set to true the contract is allowed to skip the copying of the buffer
328	/// by supplying the guard value of `pallet-revive::SENTINEL` as `out_ptr`. The
329	/// `weight_per_byte` is only charged when the write actually happens and is not skipped or
330	/// failed due to a too small output buffer.
331	pub fn write(
332		&mut self,
333		buffer: &[u8],
334		allow_skip: bool,
335		weight_per_byte: Option<Weight>,
336	) -> Result<()> {
337		self.runtime.write_sandbox_output(
338			self.memory,
339			self.output_ptr,
340			self.output_len_ptr,
341			buffer,
342			allow_skip,
343			|len| {
344				weight_per_byte.map(|w| RuntimeCosts::ChainExtension(w.saturating_mul(len.into())))
345			},
346		)
347	}
